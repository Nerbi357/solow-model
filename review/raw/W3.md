W3-01 · серьёзно · перебор ветки развилки (d17592e), траектории
Адрес `#b=s:0.1:1,d:0.098:1,n:0:0,g:0:0,a:0.9:1&k=a:set:0.35:1;g:add:0.02:1`, затем «Показать ответ». В ряду «k < 1» y, c, i нарисованы уверенными кривыми вверх, у k стоит «?»; `caseSweep` для k < 1 в долгосрочном итоге даёт `up/dunno/up/up`. Если задать g (`…g:0:1…`, свободна одна n), в ветке «?» у всех четырёх, то есть с большим числом неизвестных ответ снова увереннее.
Независимый расчёт на своих формулах: при n = 0,0025, g = 0 (k<1, k₀ = 0,951) y падает с 0,956 до 0,905, а при n = 0,05 растёт с 0,029 до 0,756. Собственная `rowsAt` страницы на n = 0,0021–0,003 даёт down/down/down/down. Полоса n+g ∈ (0,002; 0,0032) уже шага сетки (0,00825) и шага прохода через узлы (0,00198). Подпись под траекториями «(n, g) задают форму пути, но не его направление» здесь неверна.
Второй случай: `#b=s:0.148:0,d:0.129:1,n:0:0,g:0:1,a:0.678:0&k=a:set:0.173:1;s:add:0.01:1` — ветка k>1, итог c в долгосрочном «down», но при s = 0,1311, n = 0,00197 (k₀ = 1,003) c растёт: 0,8707 → 0,8724.
Случайный перебор: при α 0,25–0,6 на 257 конфигурациях промахов нет; они появляются при высокой α, когда полоса у k = 1 становится тонкой. Снимок: /tmp/claude-0/-home-user-solow-model/367e4857-4703-5d50-a517-cbfe747709de/scratchpad/review/W3/branch_paths.png

W3-03 · заметно · ячейка числа (к B3-01): отказ принять значение проходит без реакции
Подсветка `bad` не отрисовывается ни разу. В Chrome порядок такой: change, в нём `applyValue` ставит `bad`, затем `focusout`-обработчик (capture) снимает `bad` и зовёт `syncValues` — всё в одной задаче, до кадра отрисовки не доходит.
Как повторить: `#b=s:0.5:1,d:0.1:1,n:0:1,g:0:1,a:0.3:1`, ввести в ячейку s «10%» (или «0,0,1», «5бла») и нажать Enter. В ячейке молча снова «0,500». Журнал событий: change(bad=false) → blur(bad=true) → focusout(bad=false).
Раньше «10%» давало 0,99, и это было видно на картинке; теперь студент не видит ничего. Пункт 8 чек-листа («подсвечивает abc») в браузере невыполним; ui-review проверяет только, что значение не принято.

W3-06 · заметно · время перебора ветки (d17592e)
Проход через узлы складывает все узлы грубой сетки ветки в `anchors` (порядка 10⁵ объектов), чтобы взять из них четыре. Замеры в этом контейнере, лучший из трёх, прежняя и новая версия. Чистая страница, все параметры свободны, `#b=s:0.5:0,d:0.1:0,n:0:0,g:0:0,a:0.3333:0&k=a:add:0.1:1`: ветка k<1 была 314 мс, стала 418 мс (+33%). С тремя шоками (`…&k=a:add:0.1:1;K:mul:0.8:1;s:add:0.05:1`): 866 → 980 мс. Вместе с полным перебором это около 2,1 с блокировки после каждого изменения при открытом ответе. «8–141 мс» из коммита верно только при ≤ 3 свободных (A1-03: 100 → 134 мс); основная часть времени была и до правки.

W3-07 · заметно, решение на пересмотр · подпись единиц на чистой странице
g по умолчанию свободна, поэтому подпись всегда «y — выпуск, k — капитал … на единицу эффективного труда, потому что g не задан и может быть больше нуля». Так даже без шоков и при шоке по s (`#b=s:0.5:0,d:0.1:0,n:0:0,g:0:0,a:0.3333:0&k=s:add:0.1:1`). Подушевая формулировка, которой пользуются все пять задач и экзамен, не появится, пока студент не нажмёт «задано» у g (см. K5). Логически верно, но первокурсник по умолчанию видит термин, которого ещё не знает.
